# 媒体库自动整理

新增或编辑媒体库时，可填写「自动重命名模板」。模板相对于媒体库根目录，使用 `/` 分隔目录，最后一段是文件名；视频扩展名自动保留。留空关闭，升级前已存在的媒体库默认关闭。

| 场景               | 模板                                                            |
| ------------------ | --------------------------------------------------------------- |
| 电影平铺           | `{{title}} ({{year}})`                                          |
| 电影独立目录       | `{{title}} ({{year}})/{{title}}`                                |
| 剧集平铺在剧名目录 | `{{show_title}}/{{episode_code}} - {{title}}`                   |
| 剧集按季分目录     | `{{show_title}}/Season {{season}}/{{episode_code}} - {{title}}` |

例如最后一个模板可以生成 `示例剧名/Season 01/S01E02 - 第二集.mkv`。

## 模板规则

- 支持普通文字和 `{{字段名}}`，不执行表达式、函数、循环或过滤器。模板最多 1024 个字符。
- 字段：`title`、`originaltitle`、`year`、`unique_id`、`nfo_source`；剧集还可使用 `show_title`、`show_year`、`season`、`episode`、`episode_code`。
- `title` 是当前 NFO 标题，分集 NFO 中为单集标题；`show_title` 是父级 NFO 的剧名。
- `season`、`episode` 至少补齐两位；`episode_code` 组合为 `S01E02`，第零季也有效。
- 剧集目录部分只能使用父级信息，不能使用单集 `title`、`originaltitle`、`episode`、`episode_code`。
- 电影支持一段或两段路径，电视剧支持两段或三段路径，与现有扫描层级保持一致。
- 拒绝绝对路径、`..` 和无效模板。元数据中的非法文件名字符会替换为 `_`；缺失字段、保留名称或过长结果会跳过并记录原因。

## 生效时机与关联文件

模板保存后在下一次成功处理 NFO 时生效，不立即批量整理已有媒体；清空模板也不会恢复旧名称。普通扫描仅处理新增或发生变化的 NFO。

整理以完整、类型匹配的 NFO 为依据。父级信息先到达时，目录可先整理；尚未获得有效单集信息的视频保留文件名，后续单集 NFO 成功处理后再命名。

视频 ID 和观看记录保留，父子关系按整理后的目录更新。同名 NFO、外挂字幕随视频改名，字幕的语言等后缀保留。目录 NFO 以及本地素材随目录调整，并同步本地图片引用；未移动的共享素材保持原位置。

多个视频共用电影目录、平铺电影存在同名不同扩展名的视频、不同媒体争用同一目录、目标文件重名、目标目录被普通文件占用、计划中的文件与目录路径冲突、跨文件系统移动以及目录软链接等无法安全处理的情况会跳过，不覆盖已有文件。文件软链接只整理链接本身；如果 NFO 软链接需要改写内容才能保持图片引用或季信息正确，会跳过该组整理。下载器仍管理的源文件不会整理。

## 实现与恢复

`MediaLib.rename_template` 保存配置；`naming.py` 校验并渲染路径；`organizer.py` 生成文件与数据库更新计划。watcher 在元数据事务中保存待整理的媒体 ID 和待执行的入库工作流，提交后执行整理，工作流在释放媒体库锁后触发。手动更新 NFO 时也会在元数据事务中保存待整理事件；消费者在内存队列处理完后继续读取持久化事件，不依赖文件系统通知补回工作。整理中断或应用重启后，仍会使用媒体当前路径继续触发待执行的工作流。

下载仍有待搬运文件时，仅延后与其已确认目标关联的媒体组，保留待整理事件，搬运完成后自动重试，确保稍后到达的字幕和其他关联文件一起改名。其他媒体组继续处理；已完成搬运的历史任务不会因为关联文件后来被删除而阻止整理。

扫描、整理、NFO 写入、弹幕缓存读写与删除、媒体删除和下载搬运共用跨进程媒体库锁。弹幕网络请求在锁外执行，落盘时按媒体 ID 重新查找当前路径。锁文件与下载提交锁一样保存在配置的 `workspace/temp` 中，使用原生文件锁并禁用软锁降级；媒体库操作异步等待锁，进程退出后由操作系统释放。NFO 工作流携带媒体 ID，写入时重新查找当前路径及电影父项的共享 NFO。`DownloadTask.transfer_targets` 保存搬运后的实际目标，整理后同步更新，避免重试创建原名副本。整理前会恢复已发布但尚未清理完成的下载搬运，确保跨盘移动的源文件删除及恢复标记清理不因重命名而遗漏；历史任务的名称替换规则无效时，仍恢复其已知目标并跳过无法确定的目标，不阻断其他任务的回填。

文件系统移动无法和数据库共用事务，因此先校验目标路径及数据库字段约束，再将待执行计划保存在 `MediaEvent.payload`，移动后提交媒体路径与下载映射。发生中断时，后续事件、扫描或搬运先恢复计划；文件身份或权限冲突未解决前，该库暂停后续处理并输出恢复错误，其他媒体库和应用仍可正常启动。

搬运目标仅根据已有记录、有效的任务所有权标记或相同文件身份确认，不凭同名文件或下载完成状态认领。没有这些证据的历史副本不会自动关联到下载任务；同名旧文件整理移走后，新下载重试可使用腾出的原路径。

新搬运保留所有权标记，直到实际目标映射保存成功后才清理。数据库写入失败时可继续回填和重试；移动任务的恢复清理会保留原路径上后来创建或替换的文件。

RPC 下载完成时同时持久化待搬运标记和文件列表。搬运取消或失败后，同步器会继续本地搬运，不依赖远端任务仍然存在，也不重复发送完成通知；升级前的已完成任务默认不重新搬运。入库恢复和扫描会补齐视频缺失的哈希及大小；单集 NFO 的完整元数据写入后才标记为已处理，避免中断恢复后遗漏元数据更新。

已有播放页面可能仍持有旧路径，整理后需要重新加载；本功能不保证正在播放的旧地址无缝续播。
